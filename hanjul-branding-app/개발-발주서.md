## 1. 프로젝트 개요

**제품명**: 한줄 브랜딩 (Hanjul Branding) — 접속형 AI 브랜딩 도구 웹앱

**한 줄 정의**: 온라인 강의(라이브클래스) 수강생이 **수강기간 동안에만** 접속해 사용하는,
AI 기반 브랜딩 설계 도구.

**만드는 목적**: 도구를 파일로 배포하면 영구 사용을 막을 수 없다. 그래서 **파일을 배포하지 않고,
로그인·수강기간으로 통제되는 웹앱**으로 제공한다. 프롬프트(도구의 핵심 IP)와 API 키는 **서버에만**
두어, 수강기간이 끝나면 학생이 더 이상 사용할 수 없게 하고 IP 유출도 방지한다.

**결제·회원가입·강의 판매는 라이브클래스가 담당**한다. 본 웹앱은 **"누가 들어올 수 있고, 기간이
지났는지"를 확인하는 접근 통제 + AI 도구 실행**만 책임진다.

## 2. 현황 (제공되는 기준선)

작동하는 **프로토타입이 이미 존재**한다. 발주 목적은 이를 실서비스 수준으로 완성하는 것이다.

- 저장소: `heartwine1004/detail-page` · 브랜치 `claude/work-task-nqmxqr` · 폴더 `hanjul-branding-app/`
- 스택: 무의존성 Node(HTTP) 서버 + 정적 프런트(HTML/CSS/JS)
- 프로토타입에서 이미 검증된 것:
  - 수강생 이메일 로그인 / 수강기간 만료 자동 차단 / 명단 밖 이메일 차단
  - 서버가 Anthropic API로 AI 호출(프롬프트·키 서버측 보관)
  - 1인당 사용량 상한, 대화 결과(Brand Core) 내보내기, API 키 없이 도는 MOCK 모드
- 함께 제공: **시스템 프롬프트**(`prompt/system-prompt.txt` = 도구의 뇌), 브랜드 가이드(색·폰트),
  UI 시안(로그인·채팅 화면)

> 개발사는 프로토타입을 **재사용/재작성 어느 쪽이든** 제안 가능. 단, 아래 요구사항을 충족해야 한다.

## 3. 사용자 및 역할

| 역할 | 설명 | 주요 행동 |
|---|---|---|
| **수강생(User)** | 라이브클래스에서 강의를 결제한 사람 | 로그인 → AI 도구 사용 → 결과(Brand Core) 저장/내보내기 |
| **운영자(Admin)** | 대표님/스태프 | 수강생 명단·수강기간 관리, 사용량 모니터링, 공지 |

## 4. 기능 요구사항 (Functional)

### F1. 인증·로그인
- 라이브클래스 수강생 명단에 **등록된 이메일만** 로그인 허용.
- 권장 방식: **매직링크(이메일 인증)** 또는 이메일+비밀번호. (프로토타입은 이메일 확인만 하는 수준 → 보안 강화 필요)
- 세션 유지 및 만료 정책. 서버 재시작에도 세션이 살아있도록 **영속 세션 저장소** 사용.
- **[수락 기준]** 미등록 이메일·만료 계정은 어떤 경우에도 도구에 접근 불가.

### F2. 수강기간 게이팅 (핵심)
- 계정마다 **수강 종료일(expiresAt)** 을 두고, 종료일이 지나면 **자동 잠금**.
- 만료 시 안내 화면 노출("수강기간이 종료되었어요 … 재수강 시 이용 가능").
- 로그인 시점뿐 아니라 **매 요청마다** 기간을 재확인(만료 후 세션 재사용 방지).
- **[수락 기준]** 종료일 다음 날 0시부터 도구 사용 불가.

### F3. AI 채팅 (도구 본체)
- 서버가 **Anthropic API(Claude)** 를 호출. **시스템 프롬프트·API 키는 서버에만** 보관(프런트/깃 노출 금지).
- 대화 히스토리 유지, **스트리밍 응답**(권장) 또는 일반 응답.
- 모델 ID는 **환경변수로 교체 가능**하게.
- **[수락 기준]** 프런트엔드 어디에서도 시스템 프롬프트·키가 노출되지 않는다.

### F4. Brand Core(브랜드 자산) 저장·내보내기
- 사용자의 결과물을 **구조화된 Brand Core**로 저장하고, 재접속 시 **불러와 이어서** 사용.
  (스키마는 제공되는 `prompt/system-prompt.txt` 내 'BRAND CORE 스키마' 참조)
- **.md / PDF 내보내기** 제공 — **수강 종료 후에도 학생이 자기 결과물은 영구 보관**.
- **[수락 기준]** 종료된 사용자도 이전에 만든 Brand Core는 내려받을 수 있다(도구 실행만 차단).

### F5. 사용량 상한·쿼터 (비용 방어)
- **1인당 사용량 상한**(예: 대화 N회 또는 토큰 기준) 설정 가능.
- 초과 시 안내 + 차단. 운영자가 개별 상향 가능.
- **[수락 기준]** 상한 도달 시 추가 API 호출이 발생하지 않는다.

### F6. 운영자(Admin) 페이지
- 수강생 명단 **등록/수정/삭제**, 수강 종료일·사용량 상한 설정.
- **CSV 대량 업로드**(라이브클래스 명단 붙여넣기/업로드).
- 사용량·비용 **모니터링 대시보드**(인당/전체).
- **[수락 기준]** 비개발자도 명단·기간을 스스로 관리할 수 있다.

### F7. 라이브클래스 연동
- 라이브클래스의 **수강 등록/해지 연동 방식(공개 API·웹훅·CSV export) 가능 여부를 개발사가 먼저 조사**.
- 자동 연동이 가능하면 **결제 시 자동 계정 생성 / 수강기간 자동 세팅 / 해지 시 자동 차단**.
- 불가하면 **CSV 동기화**(운영자가 명단 업로드)로 구현. (최소 요구사항 = CSV 방식)

### F8. IP·프롬프트 보호
- 사용자가 대화로 **시스템 프롬프트·업로드 지식 원문을 캐내려는 시도를 거부**하는 가드레일 유지.
- 서버 로그·에러 메시지에 프롬프트/키 노출 금지.

## 5. 비기능 요구사항 (Non-Functional)

- **보안**: API 키·프롬프트 서버측 전용, 전 구간 HTTPS, 개인정보(이메일) 보호, 접근제어.
- **개인정보/약관**: 개인정보처리방침·이용약관 페이지, 최소 수집(이메일·이름 정도).
- **성능/동시접속**: 예상 동시 수강생 (○○명) 기준 안정 동작. (규모 기입)
- **가용성/백업**: DB 백업, 장애 대비. 서버 재시작에도 로그인·자산 유지.
- **로깅·모니터링**: 사용량·오류·비용 로깅.
- **UI/UX**: **모바일 우선 반응형**, 한국어, 제공된 브랜드 가이드(바이올렛+골드, Pretendard) 준수.
- **접근성**: 키보드 포커스·명도 대비 등 기본 준수.

## 6. 권장 기술 스택 (개발사 제안 가능)

- 프런트: Next.js/React (또는 동급)
- 백엔드: Node.js (프로토타입 계승 용이). 필요 시 다른 스택 제안 가능.
- DB: PostgreSQL 등 관계형 (수강생·자산·사용량)
- 인증: 매직링크(예: Resend/이메일 발송) 또는 세션 기반
- AI: **Anthropic API (Claude)** — 모델 교체 가능하게 구성
- 배포: Vercel / Render / Railway / VPS 등 (운영 편의·비용 고려해 제안)

## 7. 데이터 모델 (최소 개요 — 개발사 확정)

- `users`(email, name, …)
- `enrollments`(user, 강의, start_at, **expires_at**, quota_limit, quota_used, status)
- `conversations`(user, messages, created_at)
- `brand_cores`(user, 구조화 데이터, updated_at)
- `usage_logs`(user, tokens/횟수, cost, timestamp)

## 8. 산출물 (Deliverables)

1. 배포된 웹 서비스(운영 환경) + 스테이징 환경
2. 소스코드 일체 + 저장소 이관(대표님 소유)
3. 운영자 매뉴얼(명단 등록·기간 관리·모니터링)
4. 배포/운영 문서(환경변수, 재배포, 백업 절차)
5. 개인정보처리방침·이용약관 템플릿(법률 검토는 별도)

## 9. 일정·마일스톤 (예시 — 협의)

## 10. 견적 요청 항목 (제안서에 포함)

1. **개발비**(마일스톤별) 및 총액
2. **개발 기간**
3. **월 유지보수비**(장애대응·소규모 개선)
4. **예상 월 운영비**: ① AI API 사용료(사용량 기반, 산정 근거) ② 호스팅·DB·이메일 발송 비용
5. 라이브클래스 **자동 연동 가능 여부**와 그에 따른 비용 차이
6. 하자보수(무상 유지보수) 기간

> ※ AI 사용료는 사용량에 비례하므로, **1인당 상한 정책**과 **예상 인원**을 근거로 월 비용을 산정해 제시할 것.
