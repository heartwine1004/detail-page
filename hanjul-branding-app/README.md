# 한줄 브랜딩 — 접속형 도구 웹앱 (프로토타입)

수강생이 **수강기간 동안에만** 접속해서 쓰는 『한줄 브랜딩』 도구입니다.
결제·회원가입은 **라이브클래스**가 담당하고, 이 앱은 "누가 들어올 수 있나 + 기간이 지났나"만 확인합니다.

> 핵심 원칙: **프롬프트(도구의 뇌)는 서버에만** 있고 학생은 파일을 받지 않습니다.
> 그래서 수강기간이 끝나 접속을 막으면, 학생은 더 이상 쓸 수 없습니다.

---

## 1. 실행 (개발자용)

Node 18 이상만 있으면 됩니다. **설치할 의존성이 없습니다.**

```bash
cd hanjul-branding-app
node server.js
# → http://localhost:3000
```

- **API 키가 없으면 MOCK 모드**로 뜹니다(예시 응답). 흐름을 그대로 시연할 수 있어요.
- 실제 코칭을 붙이려면 `.env.example` → `.env` 로 복사하고 `ANTHROPIC_API_KEY` 를 채우세요.

## 2. 테스트 계정 (data/students.json)

| 이메일 | 상태 |
|---|---|
| `student@example.com` | 정상 (수강기간 내, 100회 한도) |
| `vip@example.com` | 정상 (한도 없음) |
| `expired@example.com` | **수강기간 종료** → 입장 차단됨 |

## 3. 라이브클래스와 잇는 법

라이브클래스는 커스텀 앱 연동 API가 없어서 **명단 기반**으로 잇습니다.

1. 라이브클래스에서 **수강생 이메일 + 수강 종료일**을 확인/내보내기.
2. 그 값을 `data/students.json` 에 넣습니다.
   - `email` : 로그인 허용 이메일
   - `name` : 표시 이름
   - `expiresAt` : **수강 종료일** (예: `"2026-12-31"`) — 이 날짜가 지나면 자동 잠금
   - `limit` : 1인당 대화 횟수 상한(비용 방어). `0` 이면 무제한
   - `used` : 사용량(자동 증가)
3. 라이브클래스 수강기간과 `expiresAt` 을 **똑같이** 맞추면 → 강의도 도구도 같이 만료됩니다.

> 소수 기수제라면 엑셀에서 복사·붙여넣기 수준으로 충분합니다.
> 규모가 커지면 이 부분을 관리자 페이지 / 라이브클래스 웹훅으로 자동화하면 됩니다(2차 개발).

## 4. 비용 (꼭 기억)

학생이 도구를 직접 쓰면 **API 사용료가 사용량에 비례**해 나갑니다(대표님 부담).
→ **수강료에 그 몫을 반영**하고, `limit` 으로 1인당 상한을 걸어 두세요.

## 5. 배포

- 어떤 Node 호스팅이든 됩니다 (Render, Railway, Fly, VPS 등).
- 환경변수 `ANTHROPIC_API_KEY`, `MODEL`, `PORT` 설정 후 `node server.js`.
- **API 키는 절대 프런트/깃에 올리지 마세요.** 서버 환경변수로만.

## 6. 이 프로토타입의 범위 (그리고 실서비스 전 보완할 것)

**됨(프로토타입):** 로그인 · 수강기간 만료 차단 · 사용량 상한 · 서버측 프롬프트 · 채팅 · Brand Core 내보내기(대화 저장) · MOCK 모드

**실서비스 전 보완 권장:**
- 로그인 보안 강화(매직링크/비밀번호, 세션 만료) — 지금은 이메일만 확인하는 프로토타입 수준
- `data/students.json` → 실제 DB, 관리자 페이지
- Brand Core를 대화 저장이 아니라 **구조화된 스키마로 저장/재로드**
- 라이브클래스 수강 등록/해지 **자동 연동**
- 서버 세션이 메모리에 있어 재시작 시 재로그인 필요 → 영속 세션 저장소
